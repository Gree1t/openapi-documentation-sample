Start in three commands

npm ci
npm run check
npm start

Requires Node.js 22.12 or later. Base URL: http://127.0.0.1:4010. Every operation requires Authorization: Bearer demo-token. This deliberately public value authenticates only the local fixture. All data resets when the server restarts.

Endpoints

GET/tasks

List in creation order. Optional status=todo|done and limit=1…100 (default 20). Returns data plus the count before the limit. No cursor pagination.

POST/tasks

Create from a JSON title and optional status. Returns 201 and a Location header. Status defaults to todo. Unknown fields and null values are rejected.

GET/tasks/{taskId}

Retrieve one task using a UUID. Malformed IDs return 400; well-formed IDs with no task return 404. UUID letter case is ignored.

Copy, run, compare

1. List open tasks

curl -i 'http://127.0.0.1:4010/tasks?limit=20&status=todo' \
  -H 'Authorization: Bearer demo-token'

Expected: 200 OK, with one seed task on a fresh server.

{
  "data": [{
    "id": "751e3e2a-d601-487c-b761-0bead19be760",
    "title": "Review API documentation",
    "status": "todo",
    "createdAt": "2026-10-21T10:00:00.000Z"
  }],
  "total": 1
}

2. Create a task

curl -i -X POST 'http://127.0.0.1:4010/tasks' \
  -H 'Authorization: Bearer demo-token' \
  -H 'Content-Type: application/json' \
  --data '{"title":"Review API documentation","status":"todo"}'

Expected: 201 Created, Location: /tasks/{new UUID}. Generated ID and timestamp vary.

{
  "id": "f9e0dd63-3a6e-4a80-8545-144d85853a52",
  "title": "Review API documentation",
  "status": "todo",
  "createdAt": "2026-10-21T12:58:39.900Z"
}

Titles contain 1–120 Unicode code points and at least one non-whitespace character. Surrounding whitespace is preserved. Body limit: 16,384 UTF-8 bytes. Creation has no idempotency key; retrying may create duplicates.

Errors you can act on

All JSON errors share one envelope. error.requestId matches the X-Request-Id response header.

HTTPCodeNext action
400INVALID_QUERY / INVALID_ID / INVALID_JSONCorrect the query, UUID or JSON syntax.
401UNAUTHORIZEDSupply the fixture bearer token. The response includes WWW-Authenticate: Bearer.
404TASK_NOT_FOUNDCheck the UUID or list tasks to find an existing one.
413PAYLOAD_TOO_LARGEReduce the request body to 16,384 bytes or less.
415UNSUPPORTED_MEDIA_TYPESend Content-Type: application/json.
422VALIDATION_FAILEDCorrect the fields named in error.details.
{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "Request body failed validation.",
    "requestId": "81f4d5e8-8c8e-4747-9f7d-b2e83ad903f7",
    "details": [{
      "field": "title",
      "message": "Use 1–120 characters with at least one non-whitespace character."
    }]
  }
}

An unknown route returns 404 with NOT_FOUND. Authentication runs before parameter or body validation on known routes. Error prose may evolve; clients should branch on HTTP status and error.code.

From source to a checkable contract

  1. Route inventory defines the three methods, paths and operation IDs; the fixture server consumes it.
  2. OpenAPI YAML records actual handler behavior, including defaults, bounds, headers, examples and error cases.
  3. Redocly configuration makes unresolved references and invalid examples fail lint.
  4. Contract tests compare source routes with the spec, validate examples and actual HTTP responses against schemas, and exercise success and failure paths.

Run npm run check for lint and tests; see recorded validation. Run npm run build:docs for generated Redoc reference. The sample has no production persistence, rate limiting, user accounts or external services.
